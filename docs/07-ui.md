# 07 — Screens

Next.js App Router, TypeScript, server components for data-heavy pages. Five
screens plus the wizard. Anything that does not serve the loop stays off them.

## Onboarding wizard

```
┌──────────────────────────────────────────────────┐
│  Let's make your website visible                 │
│                                                  │
│  ● 1. Your website        www.example.com        │
│  ● 2. Connect Google      you@example.com ✓      │
│  ● 3. Choose your website                        │
│         ☑ Search Console   sc-domain:example.com │
│         ☑ Analytics        Example — GA4         │
│         ○ Business Profile  Coming soon          │
│  ◐ 4. Analysing your website  312 of ~500 pages     │
└──────────────────────────────────────────────────┘
```

Step-by-step behaviour:

**1. Domain.** Accept anything a human types — `example.com`,
`https://www.example.com/`, with or without `www`. Resolve it: follow
redirects, learn the canonical origin, and store both. Do not make the user
understand the difference; that is the entire premise of the Hub.

**2. Connect Google.** One button. Identity + Search Console scopes only.
Below it, in plain words, exactly what will be read and that nothing will be
changed. Analytics is requested at step 3, on opt-in, via incremental auth.

**3. Choose.** Auto-matched resources pre-ticked, each showing what it covers
and the permission level. Every failure state from
[04-google-hub.md](04-google-hub.md#failure-states-the-wizard-must-handle)
has a designed panel here — no property found, unverified permission, several
matches, wrong account. None of them dead-ends: the user can always continue
with crawl-only analysis and connect later.

**4. Analysis.** Crawl progress with a live count. Critically, **the GSC
backfill has already populated the charts by this point**, so the user can
leave for the dashboard and find real history waiting. The wizard never shows
an empty state as a finished state.

Notes that decide whether this screen is trusted:

- The headline delta needs history. GSC backfill guarantees it on day one; the
  score delta does not exist until two snapshots do, so before then the card
  reads "first measurement — we'll show change from next week" rather than
  "▲0%".
- Counts link to pre-filtered lists. A number the user cannot click is decoration.
- "Recent changes" strip below: crawl diffs, applied fixes and verification
  outcomes. This is the loop made visible, and it is what brings people back.

## 2. Google Hub

```
Google Search Console      ✓ Connected   you@example.com
  sc-domain:example.com · synced 2h ago · 16 months of history
Google Analytics           ✓ Connected   you@example.com
  Example — GA4 (properties/123456) · goal: contact_form_submit
Google Business Profile    ○ Coming soon
Google Ads                 ○ Coming soon
```

Each card: what is connected, which account, last sync, how much history, what
data is read, and disconnect. A `needs_reauth` account shows a prominent
reconnect card with a plain explanation of what stopped working. Sync history
is one click away — a user who can see that Tuesday's sync failed will not
write a ticket about a dip in a chart.

## 3. SEO

Four tabs over the same period selector: **Queries**, **Pages**,
**Opportunities**, **Technical**.

Queries and Pages are sortable tables with sparklines, and every view that
slices by query or page carries the anonymised-clicks note. Opportunities is
the ranked issue list filtered to the SEO category — striking-distance
keywords, CTR gaps, declining pages — each with its evidence and estimated
clicks. Technical is the crawl's findings, grouped by severity, with affected
page counts.

The issue detail panel is where the loop lives: what, why, how, the evidence,
the observation history, and `[Mark as fixed]`, which queues verification and
later shows "verified on 14 March" or "this came back".

## 4. Competitors (v2)

Placeholder in v1, and honest about it: "Competitor and backlink data requires

When it ships: side-by-side metrics, content-gap list, and

than measured are labelled as estimates.

## 5. AI Strategist

Chat over the user's own data. Opens with suggested questions rather than a
blank box:

> Why did my traffic fall?  ·  What should I publish this week?  ·  Which pages
> should I improve?  ·  Find opportunities I'm missing.

Tool calls stream as visible steps ("checking your top queries…"), and every
figure in an answer links to the screen it came from. Answers cite their
window explicitly — "in the last 28 days compared with the 28 before" — because
an uncited comparison is how dashboards lose arguments.

## Cross-cutting

**Empty and partial states are designed, not incidental.** No GSC yet, crawl
in progress, fewer than 7 days of history, budget exhausted, sync failed —
each has copy that says what is known, what is missing and what to do. Most
dashboards look broken for their first fortnight; this one must not.

**Every number is explainable.** Hovering a score component shows the
sub-metrics and the `scoring_version` that produced it. Position figures note
that they are impressions-weighted averages. Anything modelled says so.

**Accessibility.** Severity is never colour alone — icon and label always
accompany it. Tables are real tables. Charts have data-table fallbacks, which
also makes them readable in the emailed report.
